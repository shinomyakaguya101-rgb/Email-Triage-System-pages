How Email Triage System processes information, where it goes, and how access can be withdrawn.

1. Operator & purpose

Jonathan operates Email Triage System for personal use. The application organizes his authorized Gmail messages and produces summaries, suggested actions, job-fit evaluations, spreadsheet records, and urgent alerts. Public account sign-up is not available. Cloud processing is being prepared and has not been verified as an active service.

2. Information processed

The application reads sender information, subjects, message body text, links, message and thread identifiers, labels, and receipt timestamps. Email text may contain personal or confidential information about the sender or other people. Attachments are excluded from AI processing.

For job alerts, it may fetch linked public job pages and process job details with Jonathan's private job-preference profile. Derived records include job-fit scores, descriptions, suggested application angles, and identifiers used to prevent duplicate records.

Processing records include message identifiers, classifications, summaries, suggested actions, completion status, and action records. Planned cloud execution also stores mailbox history checkpoints, watch expiration, retry attempts, and work status.

3. Uses & service providers

Gmail & Google Sheets

Gmail is used to read authorized mail, apply category labels, and move selected low-value promotional messages to Trash. Sheets stores sender, subject, category, summary, suggested next action, and automation action in Email_Triage_Logs, with job records in Job_Opportunities in the same spreadsheet. People with access to that spreadsheet can see its records.

Cold outreach triggers no Gmail changes, Sheets entries, or Slack alerts. Classification still reads the message and uses the configured AI provider before this category is identified. Completion state may be stored to prevent repeat processing.

Gemini API — unresolved production configuration

The implementation sends sender information, subject, and email text to Gemini for classification. Job evaluation also sends job-page descriptions and private profile context.

The currently reported API configuration uses the unpaid tier. Google's unpaid-service terms allow submitted content and generated responses to be used for product and machine-learning improvement and allow human review. Those terms instruct users not to submit sensitive, confidential, or personal information. See the Gemini API terms.

A disclosure does not resolve that restriction. An appropriate production AI-provider configuration has not been established. This draft does not promise that provider input or output is excluded from training, retained for a particular period, or never reviewed by people.

Slack

Selected urgent messages generate concise notices, relevant details, and links in Jonathan's chosen Slack channel. People with access to that channel can see the notices.

Google Cloud — planned

The prepared design uses Cloud Run for processing, Pub/Sub for mailbox-change notifications, Firestore for execution state, Secret Manager for runtime credentials, and Scheduler for watch renewal and recovery. Mailbox-change notifications contain a mailbox address and a history identifier rather than the full email body. Activation and end-to-end behavior remain unverified.

When the application fetches a public job page, that website also receives a normal web request and may record request metadata. The application does not intentionally sell email data or use it for advertising. Each provider's handling must be assessed separately.

4. Retention & deletion

The current implementation has no automatic deletion schedule for classification records, spreadsheet rows, Slack notices, or completion state. These remain until Jonathan deletes them or applies a reviewed retention rule. No fixed retention period is promised.

The application does not intentionally create a separate database of full raw email bodies. Summaries, derived details, and operational output can still contain personal data. Gmail, Sheets, Slack, the AI provider, and any activated hosting services apply their own retention practices.

Revoking Google access stops future authorized access once revocation takes effect; it does not automatically erase earlier spreadsheet rows, Slack notices, or processing state. Removing completion state can cause duplicate processing if the application runs again. Deletion therefore requires handling both stored records and future processing.

5. Access, security & your controls

The mailbox owner grants OAuth permission and can withdraw it through Google Account connections. Stopping the processor prevents further runs. Spreadsheet sharing and Slack channel membership determine who can view those outputs.

The planned cloud design uses an authenticated private processor, service identities, limited spreadsheet and secret access, and Secret Manager. These are design controls subject to deployment verification, not a claim of verified production security. Credentials and mailbox examples are excluded from this information site.

For questions, corrections, or deletion requests concerning records managed by Jonathan, use the contact below. Do not send passwords, API keys, OAuth tokens, or full mailbox contents. Deletion from provider systems outside Jonathan's control is not promised.

6. This information website

These static pages are prepared for GitHub Pages hosting. They contain no forms, account sign-in, external scripts, analytics, tracking pixels, or embedded third-party media. The pages do not set cookies or use browser storage.

When hosted, GitHub may process visitor request metadata, including IP addresses, under its privacy statement. Following an external link or emailing support uses the destination service's privacy practices. Emailing support shares your address and the contents of your message with Jonathan through Gmail.
